# 생성형 AI 답변 신뢰성 검증 전문가 시스템

사람이 AI 답변과 출처를 확인해 입력한 9개 관찰 사실에서 출발하여,
10개 규칙으로 신뢰 조건의 충족 여부를 추론하는 교육용 Python 프로그램입니다.
점수나 예 응답 개수를 세지 않고, 중간 사실을 다음 규칙의 조건으로 사용하는
**전향추론(Forward Chaining)** 을 구현합니다.

AI 답변의 진위를 자동 판별하거나 절대적 진실을 보증하지 않습니다.
LLM/API, 네트워크, 데이터베이스, 외부 Python 패키지를 사용하지 않습니다.

## 실행

Python 3.10 이상에서 프로젝트 루트로 이동한 뒤 실행합니다.

```bash
python3 -m ai_trust_check
```

- `1`: 예
- `2`: 아니오
- `3`: 해당 없음 — F6, F7, F9에만 허용하며 실패로 취급하지 않습니다.
- 잘못된 값은 다시 입력받습니다. Ctrl+C 또는 입력 종료 시 판정 없이 종료합니다.

| ID | 확인할 관찰 사실 | 해당 없음의 의미 |
| --- | --- | --- |
| F1 | 출처 제시 | 허용하지 않음 |
| F2 | 출처 접근 가능 | 허용하지 않음 |
| F3 | 출처 신뢰성 | 허용하지 않음 |
| F4 | 출처 내용이 AI 주장을 뒷받침 | 허용하지 않음 |
| F5 | 독립 자료로 교차검증 | 허용하지 않음 |
| F6 | 최신성 | 최신성이 필요하지 않은 정보 |
| F7 | 구체적 사실 근거 | 검증할 구체적 사실·수치가 없음 |
| F8 | 내부 일관성 | 허용하지 않음 |
| F9 | 적절한 불확실성 표시 | 불확실성 표시가 필요하지 않은 명확한 내용 |

**입력 모델의 한계:** 명세에는 별도의 ‘모름’ 상태가 없습니다.
특히 F4의 아니오는 실제 출처 내용이 주장을 뒷받침하지 않는다는 관찰이며,
F8의 아니오는 실제 모순이 있다는 관찰입니다. 둘 중 하나라도 아니오면
신뢰도 낮음으로 판정합니다. 출처가 없거나 접근하지 못했다는 이유만으로
F4에 아니오를 입력하면 자료 부족과 반증이 혼동됩니다.
F4 또는 F8을 확인하지 못했다면 실행을 중단하고 먼저 자료를 확인하세요.
해당 없음도 모름을 대신하는 값이 아닙니다. 원 명세의 규칙을 유지했습니다.

## 구조와 추론 과정

```text
ai_trust_check/
  facts.py       초기 사실 9개, 입력 처리 및 검증
  engine.py      Working Memory, Rule, 전향추론 및 발화 기록
  rules.py       R1~R9 규칙 데이터, R10 후처리, 최종 상태 선택
  cli.py         초기 사실·cycle·발화 이유·새 사실·최종 결과 출력
  __main__.py    python3 -m ai_trust_check 진입점
tests/
  test_system.py 자동 검증
```

Working Memory는 초기 사실(`initial`)과 추론으로 생성한 사실(`derived`)을
분리합니다. 각 cycle 시작 시 적용할 수 있는 규칙을 찾고, 발화 결과를
새 사실로 추가합니다. 새 사실은 다음 cycle에서 조건으로 사용됩니다.
이미 발화한 규칙은 다시 발화하지 않으며, 적용할 규칙이 없으면 종료합니다.

| 규칙 | 조건 | 생성 사실 |
| --- | --- | --- |
| R1 | F1·F2 예 | 출처 추적 가능 |
| R2 | 출처 추적 가능 + F3·F4 예 | 인용 근거 유효 |
| R3 | 인용 근거 유효 + F5 예 | 외부 근거 검증 완료 |
| R4 | F6·F7 각각 예 또는 해당 없음 | 사실 정보 검증 완료 |
| R5 | F8 예 + F9 예 또는 해당 없음 | 답변 자체 신뢰성 확보 |
| R6 | 외부 근거 검증 완료 + 사실 정보 검증 완료 | 사실적 신뢰성 높음 |
| R7 | 사실적 신뢰성 높음 + 답변 자체 신뢰성 확보 | 신뢰 조건 충족 |
| R8 | F4 또는 F8 아니오 | 명확한 신뢰성 문제 발견 |
| R9 | 명확한 신뢰성 문제 발견 | 신뢰도 낮음 |
| R10 | R1~R9 종료 후 신뢰 조건 충족·신뢰도 낮음 모두 미도출 + 미충족 항목 존재 | 추가 검증 필요 |

R10은 아직 생성되지 않은 사실을 조건으로 삼으므로 일반 규칙 반복문에서
분리했습니다. R1~R9의 고정점(더 이상 새 사실이 생성되지 않는 상태) 이후에만
실행하여, 신뢰 조건을 충족할 입력에 추가 검증 필요가 먼저 붙는 것을 막습니다.

모두 예인 경우의 흐름:

```text
Cycle 1: R1 → 출처 추적 가능
         R4 → 사실 정보 검증 완료
         R5 → 답변 자체 신뢰성 확보
Cycle 2: R2 → 인용 근거 유효
Cycle 3: R3 → 외부 근거 검증 완료
Cycle 4: R6 → 사실적 신뢰성 높음
Cycle 5: R7 → 신뢰 조건 충족
```

실제 출력은 각 발화의 구체적인 충족 조건도 함께 보여 줍니다.

## 시연 입력

아래 숫자를 F1부터 F9까지 차례대로 입력합니다. 이 예시는 규칙 동작을
설명하는 가상 관찰값이며 실제 AI 답변을 검증한 결과는 아닙니다.

| 사례 | F1~F9 순서의 입력 | 기대 결과 |
| --- | --- | --- |
| 모든 조건 충족 | 1 1 1 1 1 1 1 1 1 | 신뢰 조건 충족 |
| 독립 자료 교차검증 부족 | 1 1 1 1 2 1 1 1 1 | 추가 검증 필요 |
| 출처가 주장을 뒷받침하지 않음 | 1 1 1 2 1 1 1 1 1 | 신뢰도 낮음 |
| 답변 내부 모순 | 1 1 1 1 1 1 1 2 1 | 신뢰도 낮음 |
| 최신성·구체적 사실·불확실성 표시 불필요 | 1 1 1 1 1 3 3 1 3 | 신뢰 조건 충족 |

실제 과제에서는 Gemini 등에서 답변을 얻고, 답변·출처·독립 자료를 직접 확인한
다음 실행합니다. AI 답변 화면과 프로그램의 초기 사실, 추론 과정, 최종 결과를
함께 제시하면 관찰과 추론의 관계를 설명할 수 있습니다.

## 테스트

```bash
python3 -m unittest discover -s tests -v
```

9개 테스트에서 세 최종 상태, 중립 처리, 입력 재시도, 입력 중단, 터미널 실행,
역순 규칙의 연쇄 발화, R10 지연 적용, 초기 사실과 생성 사실의 분리를 확인합니다.
전체 유효 입력 `2^6 × 3^3 = 1,728`개 조합에 대해 결과의 유일성과 기대 판정,
중복 발화 방지도 검사합니다. 구현 검증 환경은 Python 3.14.7입니다.
