# 생성형 AI 답변 신뢰성 검증 전문가 시스템

사람이 AI 답변과 출처를 확인해 입력한 9개 관찰 사실에서 출발하여,
10개 규칙으로 신뢰 조건의 충족 여부를 추론하는 교육용 Python 프로그램입니다.
점수나 예 응답 개수를 세지 않고, 중간 사실을 다음 규칙의 조건으로 사용하는
**전향추론(Forward Chaining)** 을 구현합니다.

AI 답변의 진위를 자동 판별하거나 절대적 진실을 보증하지 않습니다.
LLM/API, 네트워크, 데이터베이스, 외부 Python 패키지를 사용하지 않습니다.

## 실행

Python 3.10 이상에서 프로젝트 루트로 이동한 뒤 실행합니다.

```bash
python3 main.py
```

기존 `python3 -m ai_trust_check` 실행도 지원합니다.

- `1`: 예
- `2`: 아니오
- `3`: 해당 없음 — F6, F7, F9에만 허용하며 실패로 취급하지 않습니다.
- 출처 관련 선행 조건이 충족되지 않으면 후속 질문을 생략하고 자동으로 `미확인`을 기록합니다.
- 잘못된 값은 다시 입력받습니다. Ctrl+C 또는 입력 종료 시 판정 없이 종료합니다.

| ID | 확인할 관찰 사실 | 해당 없음의 의미 |
| --- | --- | --- |
| F1 | 출처 제시 | 허용하지 않음 |
| F2 | 출처 접근 가능 | 허용하지 않음 |
| F3 | 출처 신뢰성 | 허용하지 않음 |
| F4 | 출처 내용이 AI 주장을 뒷받침 | 허용하지 않음 |
| F5 | 독립 자료로 교차검증 | 허용하지 않음 |
| F6 | 최신성 | 최신성이 필요하지 않은 정보 |
| F7 | 구체적 사실 근거 | 검증할 구체적 사실·수치가 없음 |
| F8 | 내부 일관성 | 허용하지 않음 |
| F9 | 적절한 불확실성 표시 | 불확실성 표시가 필요하지 않은 명확한 내용 |

### 출처 질문의 의존성과 미확인 상태

- F1 = 아니오: F2~F5를 질문하지 않고 `미확인`으로 기록합니다.
- F1 = 예: F2를 질문합니다.
- F2 = 아니오: F3~F5를 질문하지 않고 `미확인`으로 기록합니다.
- F1·F2 = 예: F3~F5를 질문합니다. F3·F4가 아니오여도 독립 자료 확인은
  가능하므로 F5는 계속 질문합니다.
- F6~F9는 출처 질문의 생략 여부와 관계없이 진행합니다.

`미확인`은 사용자가 숫자로 고르는 값이 아니라 선행 조건에 따른 자동 상태입니다.
생략한 이유는 입력 중 표시하고, 초기 사실과 R10의 발화 이유에도 미확인을 표시합니다.
직접 함수에 사실을 전달할 때도 같은 의존성을 검증합니다. 예를 들어 출처가 없는데
F4가 예 또는 아니오인 조합은 거부하며, 건너뛴 항목은 `Answer.UNKNOWN`이어야 합니다.

| 상태 | 의미 | 추론 처리 |
| --- | --- | --- |
| 예 | 검증 결과 조건 충족 | 해당 규칙의 조건 충족 |
| 아니오 | 확인 결과 조건 미충족 | F4·F8이면 명확한 문제, 그 외에는 검증 부족 |
| 미확인 | 출처 부재·접근 불가로 확인하지 못함 | 외부 근거 검증 부족, R8의 반증으로 사용하지 않음 |
| 해당 없음 | F6·F7·F9의 검증 필요성이 없음 | 기존대로 중립 처리 |

F4의 아니오는 **실제 출처 내용을 확인했는데 주장을 뒷받침하지 않는 경우**입니다.
출처가 없거나 접근할 수 없어 F4를 건너뛰었다면 이것만으로 신뢰도 낮음이 되지 않습니다.
다만 출처가 미확인이어도 F8에서 실제 내부 모순이 확인되면 신뢰도 낮음이 됩니다.
이 변경은 출처 질문의 선행 조건을 표현하며, 모든 항목에 임의의 모름 응답을
추가한 것은 아닙니다.

## 구조와 추론 과정

```text
ai_trust_check/
  facts.py       F1~F9·응답 정의, 질문 선행 조건 및 사실 유효성 검증
  rules.py       규칙 자료형, R1~R9 정의, R10 조건 정의
  engine.py      Working Memory, 전향추론, R10 적용 및 최종 상태 선택
  cli.py         조건부 터미널 입력, 추론 과정과 최종 결과 출력
  __init__.py    패키지 선언
  __main__.py    기존 모듈 실행을 지원하는 진입점
tests/
  test_engine.py 추론 연쇄·R10 실행 시점·잘못된 사실 검증
  test_rules.py  유효 상태별 판정·미확인과 반증 구분 검증
  test_cli.py    질문 생략·입력·출력·실행 진입점 검증
main.py          기본 프로그램 실행 진입점
README.md        프로젝트 설명과 실행 방법
```

Working Memory는 초기 사실(`initial`)과 추론으로 생성한 사실(`derived`)을
분리합니다. 각 cycle 시작 시 적용할 수 있는 규칙을 찾고, 발화 결과를
새 사실로 추가합니다. 새 사실은 다음 cycle에서 조건으로 사용됩니다.
이미 발화한 규칙은 다시 발화하지 않으며, 적용할 규칙이 없으면 종료합니다.

| 규칙 | 조건 | 생성 사실 |
| --- | --- | --- |
| R1 | F1·F2 예 | 출처 추적 가능 |
| R2 | 출처 추적 가능 + F3·F4 예 | 인용 근거 유효 |
| R3 | 인용 근거 유효 + F5 예 | 외부 근거 검증 완료 |
| R4 | F6·F7 각각 예 또는 해당 없음 | 사실 정보 검증 완료 |
| R5 | F8 예 + F9 예 또는 해당 없음 | 답변 자체 신뢰성 확보 |
| R6 | 외부 근거 검증 완료 + 사실 정보 검증 완료 | 사실적 신뢰성 높음 |
| R7 | 사실적 신뢰성 높음 + 답변 자체 신뢰성 확보 | 신뢰 조건 충족 |
| R8 | F4 또는 F8 아니오 | 명확한 신뢰성 문제 발견 |
| R9 | 명확한 신뢰성 문제 발견 | 신뢰도 낮음 |
| R10 | R1~R9 종료 후 신뢰 조건 충족·신뢰도 낮음 모두 미도출 + 미충족 또는 미확인 항목 존재 | 추가 검증 필요 |

R10은 아직 생성되지 않은 사실을 조건으로 삼으므로 일반 규칙 반복문에서
분리했습니다. R1~R9의 고정점(더 이상 새 사실이 생성되지 않는 상태) 이후에만
실행하여, 신뢰 조건을 충족할 입력에 추가 검증 필요가 먼저 붙는 것을 막습니다.

모두 예인 경우의 흐름:

```text
Cycle 1: R1 → 출처 추적 가능
         R4 → 사실 정보 검증 완료
         R5 → 답변 자체 신뢰성 확보
Cycle 2: R2 → 인용 근거 유효
Cycle 3: R3 → 외부 근거 검증 완료
Cycle 4: R6 → 사실적 신뢰성 높음
Cycle 5: R7 → 신뢰 조건 충족
```

실제 출력은 각 발화의 구체적인 충족 조건도 함께 보여 줍니다.

## 시연 입력

아래 숫자를 화면에 질문이 나오는 순서대로 입력합니다. 건너뛴 질문의 숫자는 입력하지 않습니다. 이 예시는 규칙 동작을
설명하는 가상 관찰값이며 실제 AI 답변을 검증한 결과는 아닙니다.

| 사례 | 실제 입력 순서 | 기대 결과 |
| --- | --- | --- |
| 출처 없음 (F1 → F6~F9) | 2 1 1 1 1 | 추가 검증 필요 |
| 접근 불가 (F1 → F2 → F6~F9) | 1 2 1 1 1 1 | 추가 검증 필요 |
| 모든 조건 충족 | 1 1 1 1 1 1 1 1 1 | 신뢰 조건 충족 |
| 독립 자료 교차검증 부족 | 1 1 1 1 2 1 1 1 1 | 추가 검증 필요 |
| 출처가 주장을 뒷받침하지 않음 | 1 1 1 2 1 1 1 1 1 | 신뢰도 낮음 |
| 답변 내부 모순 | 1 1 1 1 1 1 1 2 1 | 신뢰도 낮음 |
| 최신성·구체적 사실·불확실성 표시 불필요 | 1 1 1 1 1 3 3 1 3 | 신뢰 조건 충족 |

실제 과제에서는 Gemini 등에서 답변을 얻고, 답변·출처·독립 자료를 직접 확인한
다음 실행합니다. AI 답변 화면과 프로그램의 초기 사실, 추론 과정, 최종 결과를
함께 제시하면 관찰과 추론의 관계를 설명할 수 있습니다.

## 테스트

```bash
python3 -m unittest discover -s tests -v
```

12개 테스트에서 세 최종 상태, 중립 처리, 입력 재시도·중단, 터미널 실행,
질문 생략, 역순 규칙의 연쇄 발화, R10 지연 적용, 초기 사실과 생성 사실의 분리를
확인합니다. 출처 없음·접근 불가·실제 반증·내부 모순 및 이들의 경계 사례를 검증합니다.

기존의 의존성을 무시한 1,728개 조합 검사는 제거했습니다. 출처 상태는
출처 없음 1개, 접근 불가 1개, 접근 가능한 F3~F5 조합 8개로 총 10개이며,
F6~F9의 유효 응답 54개와 결합해 **실제 도달 가능한 540개 상태**만 검사합니다.
각 상태에서 최종 결과의 유일성, 기대 판정, 중복 발화 방지를 확인합니다.
모순된 선행·후속 사실 및 임의의 미확인 입력이 거부되는지도 검사합니다.

실제 CLI에서는 출처 없음, 접근 불가, 실제 반증, 내부 모순, 모두 충족,
중립 응답, 미확인과 중립, 미확인과 내부 모순의 8개 시나리오를 실행하여 확인했습니다.
검증 환경은 Python 3.14.7입니다.
